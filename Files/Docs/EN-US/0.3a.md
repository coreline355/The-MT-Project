# MT 0.3.x Alpha Documentation
**This document applies to both MT 0.3 and 0.3.1.**

---

## Scripts
- Only two scripts, **Start.mts and Main.mts.**
- Start.mts is used to configure rules and threads for the rest of the project.

- Main.mts is the script that should contain the main project code.

- **Real distinction** between local variables (only for one script) and global variables (applies to all scripts)

## Multi-Threading
- Cooperative multi-threading was introduced in this version, bringing the possibility of running more than one script at the same time.

- They are managed by the sethread and delthread commands.

- They are the main new feature of this version.

- For now, no support for thread states.

## Variables
- Supported types: number, string, but not boolean.

- Command: Variablet (set, change) (global, local) (name) (value)
- Overriding allowed

## Available commands
- Variablet (set, change) (global, local) (name) (value)
- Print (thing) (without quotes, without spaces in the text)
- Repeat
- Setflag (name) (number of times it can be called)
When a flag is called, the executor goes to the flag and continues from there; if the flag is invalid, nothing will be done.

- Gotoflag (flag name)
- setrule (rule) (value)
- sethread (thread) (script to run)
- delthread (thread)
- wait.s (seconds) **(Waits a specified number of seconds, decimal numbers are accepted.)**
- wait.kp (key) **(Waits for a specified key to be pressed before continuing.)**

### Comments

To make a comment, simply:

- "# (content) #"

## Executor Rules
- **Loudscript:** If set to 1, returns more information about the execution, useful for debugging.

- **MaxThreads:** If set to any value, prevents more threads than that value from existing. For example, if MaxThreads is set to *16*, there will be no more than *16* threads. Thread creation requests will be rejected internally if the limit is reached.

- **SpeedCap:** Set this rule to *0* and MT will run without limit! That is, it will run absurdly fast. If you don't want this, set any number in Speedcap to limit the execution speed of MT. **(DO NOT USE NEGATIVE VALUES!)**
- **ConsoleSize:** If set to *auto*, the console size will change according to the window size. If you don't want this, you can set any number to change the console size to a fixed size.

## If and comparison
This was removed because ShedExec was built from scratch in this version. So, no if in 0.3... :(

## ShedExec and Core

### The new MT executor is called **ShedExec**, bringing together the Executor and Scheduler in a single central point.
- Runs bytecode created by the parser and executes commands from it.
- Manages and creates Threads.
- It's a unified system.

### Parser
- Responsible for transforming readable code into bytecode that ShedExec understands.
- Contains basic corrupted project verification.

### Save Engine
- Responsible for managing the two scripts.
- Loads one at a time when editing.

## Known Limitations
- No support for more than two scripts
- No support for saving projects
- Critical bug in MT 0.3 that allows the flag system to run bytecode, causing serious problems and even crashes. **Fixed in 0.3.1.**
